# 室外风环境模拟优化方案

> 目标：让模拟结果贴近真实——将"目标建筑孤零零站在均匀风场中"的假设升级为"目标建筑位于真实小区楼栋环境中"。

---

## 一、问题背景

### 1.1 当前模型的核心假设

`windowBC()` 函数用以下解析公式判定每扇窗的进/出风行为：

```
物理风矢量：wx = -sin(effWindDir) × windSpd，wy = cos(effWindDir) × windSpd
窗法线投影：wn = wx × n[0] + wy × n[1]

wn < -0.05         → 迎风进风（正压 Cp，强制入流）
|wn| < 0.12×spd     → 侧向窗（吸力 Cp + 切向卷吸）
wn > 0.05          → 背风排风（完全被动开口）
```

隐含假设：
- 目标建筑**孤零零**站在无限大均匀来流中
- 无周边建筑遮挡、加速、偏转
- 风向 = 区域盛行风向（如上海夏季 112.5° SE）

### 1.2 与实测的矛盾

用户实测：上海夏季盛行东南风（112.5°），但朝东南的阳台实测为**出风口**。

可能机制：
1. **文丘里效应**：两侧楼栋之间缝隙加速 → 静压降低 → 阳台面变负压
2. **尾流遮挡**：SE 方向有更高/更密楼栋 → 来流被阻断 → 目标楼处于下游尾流
3. **绕流再附**：风从其他方向绕过上游楼栋后重新附着 → 阳台面处于负压段
4. **穿堂效应**：楼栋自身贯通通道在出口处加速 → 局部负压

## 二、方案 1：逐窗实测风向覆盖

### 2.1 设计思路

**核心原理**：既然用户已实测到"阳台是出风口"，就让用户直接告诉模拟器每扇窗的局部实际来流方向和风速——绕过区域盛行风的解析公式，用实测值驱动边界条件。

**适用场景**：用户有实地观察数据（风速计/烟雾示踪/体感判断），或从天气预报/风环境评估报告获取了目标建筑各立面局部风压数据。

### 2.2 数据模型变更

#### 2.2.1 S.wins 对象扩展

当前 `S.wins` 的每个窗对象结构：
```js
{ id, cells:[], open:true, name:'南窗' }
```

扩展为：
```js
{
  id,
  cells: [],
  open: true,
  name: '南窗',
  // ---- 新增：局部风场覆盖（可选，未设则 fallback 到全局公式）----
  localWind: null,   // null = 用全局风公式；{dir:270, spd:1.5} = 实测局部风向风速
                      // dir: 真实方位角（度，从北顺时针），0=北风(从北吹来)
                      // spd: 局部风速 m/s（可低于全局值——遮挡衰减后的残余风）
  // ---- 扩展：实测 Cp 直接指定（高级用法，覆盖 dir/spd 的推导）----
  localCp: null       // null = 由 dir/spd×法线 推导；number = 直接指定压力系数
                      // 正=迎风(进风)，负=背风(出风/吸力)，0=中性

```

#### 2.2.2 S 对象扩展


### 2.3 代码改动详解

#### 2.3.1 windowBC 改造

**改动位置**：`index.html` 第 946-999 行

**改造逻辑**：

```js
function windowBC(f){
  if(S.windSpd<=.05 && !S.useLocalWind) return;

  // 全局风矢量（不变，作为 fallback）
  const d=effWindDir()*Math.PI/180;
  const wx=-Math.sin(d)*S.windSpd, wy=Math.cos(d)*S.windSpd;
  const maxV=computeMaxV(), conv=UMAX/maxV;
  const uWind=S.windSpd*conv;
  const fe=new Float32Array(9);

  // 建筑展向范围（不变）
  let bmin=1e9,bmax=-1e9;
  for(let x=bbox.x0;x<=bbox.x1;x++)for(let y=bbox.y0;y<=bbox.y1;y++){
    if(cell[idx(x,y)]===C_EXT)continue;
    const p=x*wx+y*wy; if(p<bmin)bmin=p; if(p>bmax)bmax=p;
  }

  for(const w of S.wins){
    if(!w.open) continue;
    const n=winNormal(w);

    // ---- 新增：局部风覆盖判定 ----
    let lwx=wx, lwy=wy, lSpd=S.windSpd, lCp=null;
    if(S.useLocalWind && w.localWind){
      const ld=(w.localWind.dir + S.northDeg)*Math.PI/180;  // 局部风向也经过指北针映射
      lwx=-Math.sin(ld)*w.localWind.spd;
      lwy=Math.cos(ld)*w.localWind.spd;
      lSpd=w.localWind.spd;
      lCp=w.localCp;  // 可能直接指定 Cp
    }
    const lwn = lwx*n[0]+lwy*n[1];   // 局部风在窗法向的投影

    // 如果用户直接指定了 Cp，走简化的压力库路径
    if(lCp!==null){
      const rhoL=1+1.5*lCp*uWind*uWind;  // 注：用全局 uWind（局部 spd 可能很小）
      // Cp>0 → 迎风进流（速度沿 -n），Cp<0 → 吸力出流（速度沿 +n），Cp≈0 → 纯压力库
      const spd=0.3*Math.abs(lCp)*uWind;
      const ux=(lCp>0?-1:1)*n[0]*spd, uy=(lCp>0?-1:1)*n[1]*spd;
      for(const c of w.cells){
        if(!FLUID[c])continue;
        const x=c%NX,y=(c-x)/NX,ox=x+n[0],oy=y+n[1];
        if(inG(ox,oy)&&cell[idx(ox,oy)]===C_WIN)continue;
        feqAll(rhoL,ux,uy,fe);
        for(let k=0;k<9;k++)f[k*N+c]=fe[k];
      }
      continue;
    }

    // 以下与现有逻辑相同，但用 lwn 替代 wn
    if(lwn<-.05){
      // 迎风进流（用局部风矢量 lwx/lwy）
      const cp=Math.min(1,-lwn/lSpd);
      const spd=.55*(-lwn)*conv;
      const rhoW=1+1.5*cp*(lSpd*conv)*(lSpd*conv);  // 注意用局部风速
      for(const c of w.cells){ /* 同现有 */ }
    } else if(lwn<Math.max(.05,.12*lSpd)){
      // 侧向窗（用局部风矢量计算切向/吸力）
      /* 同现有，但 wx→lwx, wy→lwy, windSpd→lSpd */
    }
    // 背风窗：完全被动开口（不变）
  }
}
```

**关键设计决策**：
- 局部风覆盖是**逐窗可选**的：未设 `localWind` 的窗仍走全局公式
- 局部 `dir` 是真实方位角（同 `S.windDir` 口径），内部自动经过 `+northDeg` 映射
- `localCp` 是高级用法，适合从 CFD 报告直接读 Cp 值的用户

```js
function analyzeWindFace(){
  const d=effWindDir()*Math.PI/180;
  const wx=-Math.sin(d), wy=Math.cos(d);
  const inlets=[], outlets=[], laterals=[], overridden=[];  // 新增 overridden 分组

  for(const w of S.wins){
    if(!w.open) continue;
    const n=winNormal(w);

    // 如果有局部风覆盖，分析结果也用局部值
    let lwn, lwx=wx, lwy=wy;
    if(S.useLocalWind && w.localWind){
      const ld=(w.localWind.dir+S.northDeg)*Math.PI/180;
      lwx=-Math.sin(ld); lwy=Math.cos(ld);
    }
    lwn=lwx*n[0]+lwy*n[1];

    const cx={sx:0,sy:0}; /* ... 同现有 ... */

    if(S.useLocalWind && w.localWind){
      overridden.push({w,n,cx,local:w.localWind,lwn});  // 标记为"覆盖"
      // 覆盖的窗不参与标准三分类，但标注其真实进/出风方向
    } else if(lwn<-.05) inlets.push({w,n,cx});
    else if(lwn>.05) outlets.push({w,n,cx});
    else laterals.push({w,n,cx});
  }
  return {inlets,outlets,laterals,overridden,wx,wy,dir:S.windDir,spd:S.windSpd};
}
```

### 2.6 局限性

- 依赖用户有实测数据（或合理估计）
- 不解释"为什么"阳台是出风口——只反映"是"
- 多个窗同时有局部覆盖时，窗之间的相互干扰（如 A 窗出风影响 B 窗入流方向）不会被局部覆盖自动修正
- 无风时（S.windSpd=0）不触发 windowBC，局部覆盖也不会生效——这是合理的（实测无风就是无风）

## 三、方案 2：扩展域 LBM 室外绕流

### 3.1 设计思路

**核心原理**：LBM 求解器已能处理障碍物（每步做 bounce-back 反弹）。只要把周边楼栋轮廓画进扩展的计算域，求解器在更大范围内跑绕流，文丘里加速、尾流负压、遮挡偏转会**自动涌现**——不需要任何新物理。

**当前域**：144×100 格（14.4m × 10m），目标建筑占域中心约 60%。
**扩展域**：~400×300 格（40m × 30m），目标建筑占域中心约 15%，周围留出周边楼栋+绕流空间。

### 3.2 域扩展设计

#### 3.2.1 网格规模

| 参数 | 当前 | 方案 2 |
|------|------|--------|
| 网格 NX×NY | 144×100 = 14,400 | 400×300 = 120,000 |
| 计算量比 | 1× | ~8.3× |
| 单步碰撞+流动 | ~14k 格 → ~0.5ms | ~120k 格 → ~4ms |
| 7000 步收敛 | ~3.5s | ~28s |
| 内存（F+F2+RHO+UX+UY） | ~0.5MB | ~4.5MB |

**结论**：计算量增加 ~8 倍，从 3.5s 到 28s。用户可接受（后台 chunk 运行 + 进度条），但需要告知。

#### 3.2.2 坐标变换

当前所有坐标（cell/FLUID/SOLID/RHO/UX/UY）基于 144×100。扩展到 400×300 后，目标建筑从 (0,0)-(143,99) 偏移到中心区域。

**方案**：引入 `GRID_OFFSET = {x0:120, y0:100}`，目标建筑位于 (120,100)-(263,199)，四周各留 120/100 格给室外+周边楼栋。

所有引用 `idx(x,y)` 的代码不变（idx 统一为 `y*NX+x`），但：
- `bbox` 计算需要覆盖整个域而非仅建筑包围盒
- `drawBase` 需要偏移绘制目标建筑到画布中心
- `windowBC` 的 `bbox` 展向范围只考虑建筑区域

#### 3.2.3 边界条件改造

**edgeBC**（第 933 行）：从"海绵层弛豫回 ρ=1 静止"改为"注入均匀来流 + 海绵出流"：

```js
function edgeBC(f){
  const fe=new Float32Array(9);
  const d=effWindDir()*Math.PI/180;
  const wx=-Math.sin(d), wy=Math.cos(d);     // 风方向（单位向量）
  const uWind=S.windSpd*(UMAX/computeMaxV()); // 格子单位风速
  const uxIn=wx*uWind, uyIn=wy*uWind;         // 入流速度

  // 1. 入流边界：风的上游侧（wx*x+wy*y 最小的边）强制 feq(1, uxIn, uyIn)
  //    用线性判定：比较四条边的中点在风方向上的投影
  //    左边(0)：wx*0+wy*NY/2
  //    右边(NX-1)：wx*(NX-1)+wy*NY/2
  //    上边(0)：wx*NX/2+wy*0
  //    下边(NY-1)：wx*NX/2+wy*(NY-1)
  //    投影最小的 = 入流边

  // 2. 出流边界：风的下游侧 → 零梯度（零压力梯度，让流自由流出）
  //    或弱海绵：s=0.1 弛豫（比当前的 0.4 更弱，避免干扰射流）

  // 3. 侧边界：与风向平行的边 → 零梯度（自由滑移）

  // 4. 次外层（1 格内侧）：弱海绵 s=0.05（比当前的 0.4 弱，因为域大了不需要强阻尼）
}
```

**关键差异**：
- 当前 edgeBC 是各向同性的（四条边都是海绵层）
- 方案 2 需要**各向异性**：入流边是 Dirichlet（固定速度），出流边是 Neumann（零梯度）

### 3.3 2D 降维处理

2D LBM 无法反映 3D 楼栋高度差（风从矮楼上方吹过再下降到高楼迎风面）。需要近似处理：

**方案 A：高度遮蔽系数（推荐，简单）**

周边楼栋存储一个 `height` 字段（米）。如果周边楼栋比目标建筑高，其遮挡效应按"楼栋高度 / 目标建筑高度"的比例增强：

```js
// 在 bounce-back 时，C_BLDG 格的处理与 C_WALL 相同
// 但在入流边界条件中，被高楼遮挡的入流方向的风速衰减：
const shieldFactor = bldg.height / S.ceil;  // >1 = 比目标建筑高 → 遮挡更强
// 实际入流风速 = S.windSpd * (1 - 0.5*shieldFactor)  （遮挡 50%）
```

**方案 B：高度分层（复杂，留作后续）**

将 2D 域扩展为多个高度层（如低层 0-10m、高层 10-30m），各层独立 LBM 求解后耦合。工程量大，不适合当前阶段。

### 3.4 windowBC 改造（核心）

**当前**：解析公式 `feq(rhoW, -n*spd, -n*spd)` 强制设置窗格的分布函数。

**方案 2**：窗格不再设边界条件，改为**直接读取室外层格的实际 UX/UY/RHO**。

```js
function windowBC(f){
  // 方案 2 模式：不做任何强制——窗洞是纯开口
  // 室外绕流场会自然给出每扇窗外侧格的速度和密度
  // LBM 的 bounce-back 处理了固体（墙/楼栋），开口处流体自然连通
  // 无需此函数
  return;
}
```

但有一个问题：当前 `lbmStep` 的流动（pull）步骤中，固体格的分布函数被 bounce-back 交换。窗洞格（C_WIN）是流体格（FLUID=true），所以自然参与流动——**窗洞本来就是开口**，不需要 windowBC。

**但**：当前 windowBC 的作用是"在解析公式判定的迎风窗上注入入流"——这是因为在当前小域中，室外没有真实的来流（只有海绵层），所以需要"人工吹风"。

方案 2 中，扩展域的 edgeBC 注入了真实来流，室外流场会自然给出窗面的速度——**windowBC 可以完全移除**。

**但有过渡需求**：如果用户没画周边楼栋，或仍在小域模式下运行，仍需要 windowBC。所以：

```js
function windowBC(f){
  if(S.domainMode === 'extended') return;   // 扩展域模式：室外有真实来流，不需要人工窗边界

  // 小域模式（当前行为不变）
  if(S.windSpd<=.05) return;
  // ... 现有全部代码 ...
}
```

### 3.5 analyzeWindFace 改造

扩展域模式下，`analyzeWindFace` 不再用公式判定，而是**实测**每扇窗的净流量：

```js
function analyzeWindFace(){
  if(S.domainMode === 'extended' && S.sim){
    // 从模拟结果读取每扇窗的实际流速方向
    const k = computeMaxV()/UMAX;
    const inlets=[], outlets=[], laterals=[];
    for(const w of S.wins){
      if(!w.open) continue;
      const n=winNormal(w);
      let q=0;
      for(const c of w.cells){
        if(!FLUID[c])continue;
        const x=c%NX,y=(c-x)/NX,ix=x-n[0],iy=y-n[1];
        if(inG(ix,iy)&&cell[idx(ix,iy)]===C_WIN)continue;
        q+=-(S.sim.ux[c]*n[0]+S.sim.uy[c]*n[1]);  // 物理单位
      }
      const cx={sx:0,sy:0}; /* ... */
      if(q>.01) inlets.push({w,n,cx,q});
      else if(q<-.01) outlets.push({w,n,cx,q});
      else laterals.push({w,n,cx,q});
    }
    return {inlets,outlets,laterals,measured:true};
  }
  // 小域模式：现有解析公式逻辑
  // ...
}
```

### 3.9 测试计划

| 测试项 | 预期结果 |
|--------|---------|
| 标准域、无周边楼栋 | 与现有完全一致（Qin 3983, ACH 20.2） |
| 扩展域、无周边楼栋 | Qin 略增（来流更自然），ACH 相近 |
| 扩展域、SE 方向有高楼栋 | SE 阳台面风速降低，可能从进风变为侧向/出风 |
| 扩展域、两侧有窄缝楼栋 | 缝隙处风速增大（文丘里），缝旁窗面负压 |
| 扩展域、上游有宽楼栋 | 目标建筑处于尾流区，各窗流量重新分配 |
| 计算时间 | 标准域 ~3.5s，扩展域 ~28s（或自适应 ~19s） |
| 画布平移/缩放 | 扩展域画布可拖拽滚动、滚轮缩放 |

### 3.10 局限性

- **2D 限制**：无法反映楼栋高度差（风从矮楼上方吹过再下降）→ 方案 A 高度遮蔽系数只是近似
- **计算量**：~8 倍计算量，用户需等待 ~28s（可加后台运行 + 通知）
- **周边楼栋精度**：用户手画的楼栋轮廓是粗略的，真实小区布局可能更复杂
- **内存**：4.5MB 在低端设备上可能紧张（但现代浏览器通常有 100MB+ 限额）
- **收敛判断**：扩展域的收敛特征可能不同（射流更长），MAXSTEP 可能需要调大

### 推荐顺序

1. **先做方案 1**（工程量 ~300 行代码，~2h）
   - 立即解决用户"阳台是出风口"的模拟需求
   - 不改变物理引擎，风险低
   - 为方案 2 提供用户验证基准（有了实测覆盖值，扩展域的结果可以对照）

2. **后做方案 2**（工程量 ~800 行代码，~6h）
   - 物理上最自洽
   - 工程量大，涉及域扩展、画布改造、性能优化
   - 方案 1 的逐窗覆盖在方案 2 完成后仍可保留（作为"我没有画周边楼栋但知道某窗是出风"的快速修正手段）

## 五、风险与回退

### 方案 1 风险

| 风险 | 等级 | 缓解措施 |
|------|------|---------|
| 用户不知道局部风向填什么 | 中 | 提供填写指引 + 默认值 = 全局风向 |
| 多窗覆盖时相互干扰未修正 | 低 | 接受——比全局公式好就已足够 |
| localCp 误填导致发散 | 低 | 钳制 Cp ∈ [-1.5, 1.5] |

### 方案 2 风险

| 风险 | 等级 | 缓解措施 |
|------|------|---------|
| 计算量 28s 用户无法接受 | 高 | 自适应分辨率 + 后台运行 |
| 内存 4.5MB 在低端设备紧张 | 中 | 检测 navigator.deviceMemory，<4 时提示用标准域 |
| 收敛特征改变（射流更长） | 中 | MAXSTEP 从 7000 调到 12000，收敛判据放宽 |
| 画布平移/缩放引入 bug | 中 | 用 transform 矩阵而非改坐标计算 |
| 周边楼栋手画精度不足 | 低 | 接受——定性正确比定量精确更有价值 |

### 回退方案

两个方案都通过 `S.domainMode` / `S.useLocalWind` 开关控制，默认关闭时行为与当前完全一致。任何问题都可一键回退。
